# Chronos Light: Telegram-бот аналитик (ЛР 3)

Бот на **aiogram 3** - сервис-помощник для игры Chronos Light.

**Почему это не копия игры в чате.** Игровая логика (лабиринт, свет, движущиеся стены) остаётся
в Pygame-приложении. Бот работает только с данными, которые игра выгружает: файлом `records.csv`
(ЛР 2). Игрок присылает этот файл боту, а бот проверяет его и строит таблицу лидеров, личную
статистику и достижения, а также рассылает уведомления.

## Возможности

- 🏆 таблица лидеров (лучшая победа каждого игрока);
- 📊 личная статистика по имени игрока и 🎖 достижения;
- 📤 приём `records.csv` из чата: разбор, проверка каждой строки, защита от дубликатов;
- 🔔 подписка на уведомления о новых результатах;
- 📣 для администратора: рассылка подписчикам и просмотр лога бота (`/log`, `/broadcast` или кнопки).

Управление через инлайн-кнопки; один «экран» на пользователя правится через `edit_message_text`
(чат не засоряется).

## Запуск

1. Создайте бота в Telegram у **@BotFather** (`/newbot`) и скопируйте токен.
2. Установите зависимости (Python 3.12+):
   ```
   cd py_bot
   pip install -r requirements.txt
   ```
3. Создайте `py_bot/.env` по образцу `.env.example`:
   ```
   BOT_TOKEN=123456789:AAAA...
   ADMIN_IDS=123456789
   GAME_TIME_LIMIT=90
   ```
   Свой id можно узнать у бота @userinfobot. `.env` в `.gitignore`, в репозиторий его добавлять нельзя.
   Если токен попал в репозиторий, отзовите его у @BotFather (`/revoke`) и выпустите новый.
4. Запустите: `python bot.py` (из папки `py_bot`). Бот работает через long polling.
   Запущенная копия должна быть одна: две копии с одним токеном дадут ошибку 409 Conflict.

Для проверки используйте отдельного тест-бота.

## Структура

| Файл | Назначение |
|---|---|
| `bot.py` | точка входа, хендлеры команд и кнопок, FSM, обработка ошибок, рассылка |
| `session.py` | stateless JSON-сессии по `user_id` |
| `analytics.py` | разбор и проверка CSV, база результатов, таблица лидеров, статистика, достижения |
| `keyboards.py` | инлайн-клавиатуры |
| `states.py` | состояния FSM |
| `middlewares.py` | журнал апдейтов, восстановление режима из сессии, антифлуд |
| `config.py` | токен и параметры из `.env`, пути, лимиты |
| `examples/` | `records_ok.csv` (корректная выгрузка) и `records_broken.csv` (с ошибками) для проверки |

Создаются при работе: `sessions/` (сессии), `data/scores.csv` (общая база), `bot_flight.log` (лог бота).

## Архитектура

**Stateless-сессии.** Профиль пользователя лежит в `sessions/<user_id>.json`. На каждое действие
бот читает файл, меняет поле и записывает обратно (атомарно: временный файл + `os.replace`).
Глобальных словарей с профилями нет, сессии разных пользователей разделены физически, а после
перезапуска бота ничего не теряется. Повреждённый или отсутствующий файл заменяется новой сессией.

```json
{
  "user_id": 123456789,
  "state": "MENU",
  "name": "Иван",
  "subscribed": true,
  "screen_message_id": 412,
  "screen_chat_id": 123456789
}
```

**FSM и сессия работают в паре.** FSM отвечает на вопрос «что бот сейчас ждёт»: `MENU`, `UPLOAD`
(файл), `WAIT_NAME` (имя), `BROADCAST` (текст рассылки). Сессия отвечает «кто пользователь и что о
нём известно». Режим дублируется в `session["state"]`, и если бот перезапустился (MemoryStorage
пуст), `RestoreModeMiddleware` возвращает режим в FSM. Выход из любого режима: кнопка «Отмена»,
`/cancel`, `/start`. Команды зарегистрированы без `StateFilter`, поэтому работают из любого состояния.

**Один экран на пользователя.** `show_screen()` правит сообщение через `edit_message_text`.
Ошибка `message is not modified` игнорируется, а если экран удалён (`message to edit not found`),
отправляется новое сообщение. `chat_id` хранится рядом с `message_id`. Новые сообщения шлются только
для уведомлений, рассылок и после команд.

**Приём файла.** Хендлер загрузки сработает только в состоянии `UPLOAD` (`StateFilter`). До
скачивания проверяются размер (до 1 МБ), расширение (`.csv`/`.txt`) и mime-тип. Затем файл
скачивается в память, декодируется как `utf-8-sig`, и `analytics.import_scores_text` (в потоке, через
`asyncio.to_thread`) разбирает и проверяет строки. Результат: «добавлено / дубликатов / отклонено»
и первые ошибки.

**Верификация строки.** Заголовок должен быть `Имя, Статус, Время, с, Сдвигов стен, Дата`; 5 полей;
имя 1-16 печатных символов; статус `Победа` или `Поражение`; время конечное, > 0 и ≤ 2 × лимит
времени игры (`GAME_TIME_LIMIT`); сдвиги стен от 0 до 100 000; дата формата `ГГГГ-ММ-ДД чч:мм:сс`.
Битые строки не ломают разбор остальных.

**Таблица лидеров.** Берётся лучшая победа каждого игрока (имена без учёта регистра). Порядок:
1) меньше время, 2) меньше сдвигов стен, 3) раньше по дате. В таблицу попадают только победы,
показывается топ-10.

**Достижения:** «Первый выход» (победа), «Скороход» (победа быстрее 45 с), «Упорный» (5 партий),
«Ветеран» (3 победы), «Без осечек» (3 победы подряд).

**Антифлуд.** Кнопки не чаще раза в 0,6 с на пользователя, экраны правятся, а не дублируются,
рассылка идёт со скоростью около 20 сообщений в секунду. Для кнопок вызывается `callback.answer()`
(в `try/except` на случай просроченного запроса).

**Безопасность.** Токен только из `.env`. Права админа проверяются по `ADMIN_IDS` и в командах, и
в кнопках (`callback_data` можно подделать). Все данные из файлов и имена экранируются `html.escape`
перед выводом в HTML-режиме. Длина `callback_data` не больше 64 байт (только код действия).

**Ошибки и логи.** Глобальный `@dp.errors()` пишет traceback в лог и отвечает пользователю
«Временный сбой». Отправка при сетевом сбое повторяется. В `bot_flight.log` пишутся:
каждый апдейт (кто и что нажал или прислал), загрузки файлов, подписки, рассылки, попытки доступа без
прав, ошибки. Формат строки: `2026-03-05 14:21:07 | INFO | user=123 кнопка top`.

## Выгрузка игры (пример)

`examples/records_ok.csv` - это формат `records.csv`, который создаёт игра:

```
Имя,Статус,"Время, с",Сдвигов стен,Дата
Иван,Победа,52.3,411,2026-03-05 14:21:58
Иван,Поражение,90.0,640,2026-03-05 14:30:10
Мария,Победа,39.7,350,2026-03-06 10:12:09
```

## Как проверить (этап 7)

1. `/start` - меню; кнопки работают, экран правится на месте.
2. «Загрузить результаты» -> `examples/records_ok.csv`: «Добавлено 11». Повторная отправка: «Дубликатов 11».
3. `examples/records_broken.csv`: добавлены только корректные строки, ошибки показаны. Файл `.exe` или
   большой файл отклоняется до скачивания.
4. «Сменить имя» -> `Иван`: «Моя статистика» и «Достижения» заполнены.
5. Два аккаунта: у каждого своя сессия в `sessions/`, имена и подписки не пересекаются.
6. Удалите `sessions/<id>.json`: при следующем действии создаётся новая сессия.
7. Подписка на втором аккаунте; загрузка файла с первого: второму приходит уведомление.
8. Админ: `/broadcast`, `/log`; у обычного пользователя «⛔ Нет прав».
9. Остановите бота во время режима загрузки, запустите снова: режим восстановлен из сессии.
